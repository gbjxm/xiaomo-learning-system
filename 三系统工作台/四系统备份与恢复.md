# 四系统本机数据备份与恢复

日期：2026-10-05。统一数据备份补齐领航室；沿用原 `web/Backup-PersonalSystem.ps1` 入口。备份是手动、本机的数据快照，没有增加日程、后台任务或云端上传。

## 日常备份

先完成正在进行的保存，再在 PowerShell 运行：

```powershell
& 'D:\codex\小陌的学习系统\web\Backup-PersonalSystem.ps1'
```

成功返回 `ok:true`、实际 ZIP 位置、SHA-256、文件数及 `navigationSaved:true`。包保存在项目根的 `备份/个人终端-时间-随机编号.zip`。保存失败或检查未通过时不会发布半成品 ZIP，原资料保留。

| 数据 | 范围与权威位置 |
|---|---|
| 学习及个人内容 | `运行记录/`，包括学习笔记、创作内容、观影台账、`.自然记录/` 与 `.学习提交/` 回执及冻结提交目标 |
| 界面与工作台 | 学习 UI 草稿、工作台关联与阅读位置的原始文件 |
| 素材观察室 | 原 SQLite 在线一致性快照及附件；登记附件的路径、长度和哈希核对 |
| 信息收集 | 原 SQLite 在线一致性快照、`sources.json`、`rules.json`、`visual_assets.json`、图片与登记证据 |
| 领航室 | 按当前 `navigation-connection.json` 定位；当前领航状态、个人处境、人生罗盘、连接配置、入口说明、全部 `依据/` 文本（含原始转写），以及状态显式关联的领航目录内 Markdown/文本 |

领航文件在包内统一放到 `领航室/`，但清单保留实际原目录、schema、revision、状态哈希及各类稳定编号。`navigation-connection.json` 与领航 `connections.json` 保持原字节；不会将原系统地址悄悄改成恢复目录。

不打包账号/模型/代理配置、运行源码、旧备份、临时锁/临时文件、知识树、正式影视项目及完整媒体库。领航目录以外的来源链接仅保留引用，不递归追入其他系统；缺失或越界的显式关联文档会报错，不能把缺件包当作完整包。领航 `依据/` 出现本范围未纳入的二进制文件时也会报明缺口。

两个 SQLite 各自一致，不声明跨库同一时刻事务。业务文件复制前后按清单及 SHA-256 核对；保存锁存在、文件新增/消失或内容变化时拒绝完成。遇到此类错误，先完成保存或核对遗留锁，再重试；备份工具不会清理原锁或修复原记录。

## 校验与全新隔离恢复

```powershell
python -B -X utf8 'D:\codex\小陌的学习系统\web\unified\backup.py' --verify 'D:\codex\小陌的学习系统\备份\实际文件.zip'
python -B -X utf8 'D:\codex\小陌的学习系统\web\unified\backup.py' --verify 'D:\codex\小陌的学习系统\备份\实际文件.zip' --restore-target 'D:\codex\小陌的学习系统\验证\三系统整合\恢复核对-全新名称'
```

恢复仅接受 `验证/三系统整合/` 下不存在的新目录，拒绝正式/已有目标、目录重定向、符号链接、危险包路径、Windows 保留名及数据范围外的文件。旧三模块 v1 包仍能核验/恢复，但不会凭空补出未备份的领航数据。

恢复后逐文件核对哈希，并生成：

- `RESTORED_ISOLATED.json`：原始清单与 `enabledAsProduction:false`。
- `RECOVERY_VERIFICATION.json`：两库 `quick_check`、外键及行数、数据库身份、领航状态身份和未完成学习/自然提交列表。

**新路径里的原字节恢复目录用于完整性核对，不能直接冒充正式运行目录。** 原文件内的根路径、scope、storeId、内容身份与请求哈希均保留，因此消费者会拒绝错误路径身份。工具不自动覆盖正式资料，也不提供异地换根迁移。

真正灾后恢复需要先核对原目录、当前资料保护、运行代码与连接配置；在确认的原位置按清单映射数据（领航按清单原目录），再通过各模块受控入口读回及续接。不能直接把 `领航室/` 当成新的正式位置。跨机器/异地换根另需受控迁移，不在本次启用范围。

## 本轮证据与边界

19 项隔离备份测试通过：四系统范围、隐藏回执、领航转写与文档、实际 WAL 的已提交/未提交区分、变化检测、篡改/缺库拒绝、真实 Junction 拒绝、旧包兼容等。首次符号链接测试因 Windows 缺少符号链接权限失败，改用实际 Junction 完成同类验证；保留首次结果，没有把跳过写成通过。

真实备份首次运行暴露了一个专项测试未覆盖的组合：WAL 数据库快照加图片目录二次校验会生成暂存 `-wal/-shm`。已仅对完成且关闭的暂存快照使用 immutable 只读，正式源继续在线读取 WAL；新增实际 WAL＋图片目录回归通过，保留失败记录。

原统一备份 10 项回归亦通过，含登记附件哈希不符拒绝。独立复核补齐了 v1/v2 包恢复收据保留名拒绝；`--verify` 仅核验包哈希与清单，SQLite 实际完整性复核发生在隔离恢复阶段。

另有 12 项合成原路径恢复检查通过：按清单保护合成原件，恢复到同一绝对路径；不改身份或任何业务 history/请求哈希。原消费者可读同一笔记、W 编号和创作编号；三类已提交自然请求原样重放且不再调用模型；`prepared` 自然回执及 `interrupted` 学习冻结目标恢复后依原 CAS 完成同请求，再沿原 ID 补充。UI 原 storeId/草稿、工作台身份、领航原记录与新追加均核对，原字节异地恢复副本始终保持哈希不变。

测试使用合成数据及现有可信代码，没有把演练写入正式经历；SQLite 测试覆盖一致性、外键/行数和原字节，不能据此称所有业务 UI 都已在真实恢复副本运行。真实本机包与隔离只读恢复的最终收据由本轮启用记录补充。验证目录为 `验证/三系统整合/前两阶段收尾-20261005-A/`。
