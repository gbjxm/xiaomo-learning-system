## 日常协作与写入

- `orchestrate-personal-learning` 是学习总入口，按需调用六个专业技能。无需每次启用全部技能或新建多个用户任务。
- 课程笔记、看片感想、创作想法及其补充先按总协调的 `references/natural-recording.md` 分流，网页与 Codex 共用 `node web/learning/intake-cli.mjs`。先核对已有对象，保留原话与独立 AI 回应，沿稳定编号接续；保存后回读并提供网页入口。仅登记不启动路线、练习或能力判断；课程 note 不强制 taskId，也不改最近任务的目标或停止处。
- 小陌已授权本项目日常自然收尾保存；完成一块交流、明确请求的安排、复盘或暂停时，依 `运行约定.md` 保存并简短告知，不反复询问。用户当次明确不保存时遵从。
- 个人状态只由总协调职责汇合写入。专业技能直接使用时，由同一执行者在收尾承担该职责，不递归调度。先重读、保存依据，最后更新当前状态并回读。
- 明确请求的安排保存为待执行；实际活动、能力证据、用户自述、AI 判断和候选建议分开。测试和系统维护不生成真实学习进展。
- 进入安排或练习时，除最新停止处外，按情境查看 `运行记录/阶段安排.md` 中仍有效的已采用改进；带回结果后对照原观察点更新同一条目，候选或停用做法不自动加入任务。
- 自然记录走上述 intake；已核对身份的内容编辑与回读仍可按 `运行约定.md` 使用 `node web/content/cli.mjs` 的 `bootstrap`、`list`、`detail`、`save --input <JSON文件>`。仅有片名也能登记；日期、集数或看完与否未提供就保留未知，后续进度或再次观看更新同一 W 编号。明确只聊不保存时不提交；引用、假设、推荐不成为本人经历。不为了留一条内容新建学习任务或能力进展。
- 新创作内容归 `运行记录/我的内容/*.json`，`运行记录/观影记录.md` 是唯一观看台账；课程 note 归原 `运行记录/学习记录/`，网页投影同一条目，不复制第二套课程笔记。旧 UI 草稿、书签及领航来源在共享页只读引用，继续原内容走原入口；正式创作工程仍归原影视工作流。保存来源链接、转写或文件位置不代表已经看过、听过媒体。
