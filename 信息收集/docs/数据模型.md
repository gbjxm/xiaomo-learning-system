# 实施边界与数据模型

这是个人 localhost 创作机会库。借鉴 AIHOT 的信源可追溯、分类浏览和更新记录体验，使用独立实现与名称。运行不需要账户、凭据、付费接口或云服务。只在点击检查更新或运行命令时检查一次；启动与打开页面仅看本地数据。

## 统一实体

`competition` 比赛征集、`creator_program` 长期创作者计划、`limited_benefit` 限时福利、`rule_update` 平台规则更新共同存储。每条具有平台、主办方、官方 URL、报名/加入入口、年度轮次、标签、资格、作品要求、操作步骤、独立奖励类别、版权限制、证据及缺失字段。URL + 年度轮次用于去重，不同轮次不自动合并。

## 三组时间

- 公告发布时间：用于“新发布”，不决定报名状态。发现时间不是发布时间。
- 报名/加入时间：明确起止、官方明确常年开放、分批分期、官方未说明四种机制。缺截止不等于长期有效。政策开始生效与结束另存；无法确认正文或时间时显示待核验。
- 奖励有效期：现金、积分、算力、流量、推广与展映独立存储，积分有效期不作为活动截止时间。

原文未注明时区时保留未知；在边界附近给出待核验，远离边界可显示报名期内，并提示时区未明。未明确截止不自动归档。已核截止过后归档而不删除。

## 长期机制

独立保存加入资格与加入方式、收益计算、结算规则、持续达标条件、退出条件、生效版本和核验时间。长期机制参与搜索及匹配排序；无截止也不会被过滤掉。

## 证据与版本

人工移交种子、实时网页抓取、人工补充核验分开。移交中未提供核验时刻的字段保留为空。HTTP 成功、取得正文和完成核验是不同事件。页面文本变化进入待复核差异，不自动覆盖已有人工核验规则。版本保留修改前后字段；刷新不重复造版本。用户关注和笔记不会被刷新覆盖。

## 更新结果

每个信源保存最后尝试、最后抓到内容、最后成功完整检查时间，逐次报告成功零新增/成功有新增或变更、部分提取、失败、待核验。主页可访问、登录页或图片规则不算完整接通。更新使用进程锁，重复点击复用同一轮任务。外部网页只作为数据解析，不执行其中指令、脚本或任意外链。

针对性修复后增加三个独立覆盖维度：公开正文、规则字段、本账号资格。正文“文本完整”仅表示已识别文章容器或公开JSON组件的文字完整取得，图片引用和外链仍另列未核。LibTV保存“嵌入正文已取得”，不视作外链全文完整。规则完整检查延用原标准；不要求先登录用户账号，也不把公开AI准入条款缺失补成允许。个人资格未连接时独立显示未核验。

来源、每次尝试和每份正文证据保存覆盖维度；正文完整取得与规则完整检查成功分别计时。SQLite从版本1平滑增加字段至版本2，不回填旧检查为新维度成功，不覆盖人工条款、笔记或历史。原文变化包含提取器升级造成的变化，继续保留待复核标记，不等同于官方政策修订。

## 实施步骤

2026-09-30扩充继续使用原SQLite版本2；新增内容保存在条目JSON，不重建或覆盖数据库。

- `time.deadline_raw`保留“24时”原文，实际比较用次日零时；时区未明继续保守判断。
- `time.month_period`仅保存YYYY-MM。即梦7–12月窗口不补造起止日或时刻，月份过后保留待核，不自动归档。
- `time.deadline_tentative`和`time.conflict`独立于明确截止，暂定/冲突不自动视为开放或已截止。
- `relations`关联母计划、限时子活动、专属赛道或规则，目标为稳定ID。子活动不继承或改变母计划时间、奖励。详情支持双向查看。
- `assessment`保留候选/限制/尽调/推广/历史/核心版权不建议用途、官方AI规定与个人资格未核状态。检索相关度不是作品正式推荐榜。
- `record_context=historical_reference`允许已颁奖或AI限制参考进入历史浏览，但不伪造报名截止。
- `fees`与`reward_conflict`独立保存费用和奖项口径冲突。总奖池、单奖、积分、算力、展映及投资互不相加。
- 字段记录度只反映已填写信息比例，不代表规则完整或账号/作品资格通过。来源仍分别报告正文、规则、账号，且显示清单发现/指定URL核对/主页或未适配能力。

1. 校准上述实体与时间机制，登记官方种子和未适配信源。
2. 实现 SQLite 存储、保守解析、单次检查、差异记录与归档。
3. 实现本地分类浏览、搜索、筛选、详情、关注、笔记、信源报告和变更查看。
4. 验证解析、时间边界、失败和重复点击、启停与持久化，并留存浏览器截图。


## 首页时间与核验排序（2026-09-30）

派生状态新增`window`：官方日期或月份范围内但不能确认开放。月份包络只在内存计算，未知时区的月初/月末与政策生效/终止边界为uncertain；数据中不补造日时。

API派生`priority`包含公开时间证据分组、保守UTC截止排序值、核验/发布排序值；个人资格及本机失败分维度，不改变已核事实。原记录没有新增priority持久字段。

人工补核可含`public_review`（日期、方法、已核字段、剩余字段）、`cash_tiers`（条件、基础、画布加奖、币种、税口径）、`canvas_requirements`、`contact_email`/`entry_status`。这些字段由本轮官方公开交接证据补入，原证据和版本保留，整体partial不因单个字段已核升为complete。
