# 学习复盘与调整建议

先读项目共享契约 [运行约定.md](../../../运行约定.md)。专业职责读取有关记录并返回复盘与建议，由 `orchestrate-personal-learning` 汇合保存；不直接修改运行状态、重排计划或代替具体作品复盘，也不递归调用本项目其他专业技能。

## 根据真实需要决定回顾深度

- **自然小块或当天收尾**：先回应本次做了什么、用户实际感受到什么；只回看影响下一步的收获、卡点和停止处。没有必要时几句话即可，不强制产出方法论或检验。
- **周回顾**：结合已采用安排与实际活动，检查推进是否合适、时间估计是否偏差、任务之间能否接上；提出下一周的局部调整。
- **月或阶段回顾**：结合代表性表现与现实变化，判断重点是否仍值得投入、哪些暂时够用、哪些需要继续验证；不每天重做长期方向。
- 用户只想交流、欣赏作品或休息时，尊重当前意图，不自动启动完整复盘。周月回顾按需发生，不生成到期必须补交的任务。

## 使用已有事实

按本次范围读取 `运行记录/当前状态.md`、`运行记录/阶段安排.md`、`运行记录/能力依据.md`，以及相关 `运行记录/学习记录` 或 `运行记录/复盘` 中的现有内容。只取有关部分，引用活动与作品入口，不重抄全部日志、知识资料或项目记录。

用户在对话中新提供的经历可作为明确标注的自述；没有记录不能证明没有学习、没有进展或不够自律。缺少关键事实时提出一个具体问题，或给出保留限制的回顾，不编造活动、日期、时长、成果和失败。

区分个人学习表现、资料质量、工具与素材限制、作品效果、观众反馈和时间安排。作品的成败可以提供学习线索，但不能直接认证或否定个人全部能力。AI 给出的原因只能按证据标为已知或待验证的假设。

## 让回顾改变下一次做法

围绕实际问题选择必要内容：原先希望达到什么、实际有哪些结果、哪些做法有效、问题可能来自哪里、下次值得调整什么。不把这些变成每轮必填表。

优先保留有效做法，针对反复出现或妨碍推进的问题提出小范围调整。建议应能说明所依据的活动，以及继续、减量、补充解释、换材料、增加练习、改变顺序或暂停的原因；没有明确缺口时可以建议保持现状。

对值得在下一次相关任务继续用的改法，说明适用情境、具体变化和要观察的结果，连同采用依据交给协调环节，按 [已采用改进的接续规则](../../../运行约定.md#把已采用的改进带回下一次任务) 汇合。用户未采用的仍是建议，不自动为所有知识安排复习。

如果这次反馈对应一项已采用改法，读取它原来的问题和观察点，说明本次是否实际使用、结果有什么变化、证据来自哪里以及条件是否可比；已经有这些信息就直接回应，不重复问卷。尚未使用、只报告“做完了”或缺少结果时保留未知，不能把完成动作当作方法有效。

返回给协调器的结果应能对应到原条目及本次活动。有效的部分可建议继续保留；没有改善、增加负担或条件不同则如实说明，给出必要的小范围调整。一次体验不确立普遍因果结论，是否调整长期做法仍依用户选择。

## 支持重新开始与适度督促

休息、分心或中断后返回时，先找回停止处并提出容易继续的一步；不要求先补日志、解释所有空白或补齐欠下的任务。计划过满时先考虑减量或重排，不默认加班。

投入分散或频繁换方向时，只有在当前记录或用户自述支持时才指出对既有重点的具体影响，帮助作出有意识的取舍；不做人格或自律诊断。

督促发生在当前对话及用户主动返回的节点。不创建后台监控、计时、自动催促或定时提醒；如用户另行提出，交回协调器作为独立需求处理。

## 返回与完成

返回简短回顾、有依据的解释、尚待确认之处和必要调整建议，并指出适用的日、周或阶段范围。既有活动只作引用，新的自述与推断分别标明。

由总协调按共享契约保存本次真实回顾，更新停止处或汇合已采用调整。直接被用户调用时，到自然保存节点，由当前执行者在同一对话读取总协调保存规则并履行该职责，不递归开启协调会话、不要求切换任务或重复授权。

没有真实新活动时可以做安排回顾或讨论调整，不生成一轮已完成学习的记录。未采用建议保持建议状态。
