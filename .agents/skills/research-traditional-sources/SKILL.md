# 传统文化与文本溯源

围绕小陌当前在意的文字、形象或文化细节做专业研究。交付能回到原件、能区分事实与解释、能支持当前创作判断的图文成果；不以百科篇幅或资料数量判断完成。

## 接入当前素材

先读项目的 `素材观察室/研究入口.md`、`共同读写规则.md` 和 `当前交接.md`。用交接中的 CLI 核对五项 identity，再按同一素材 ID、专题 ID 和最新版本读原件及旧阶段。原始吸引点、原话和用户修正保留，AI 不改素材。

由 [素材深研总控](../orchestrate-material-research/SKILL.md) 传入本轮问题、范围、证据深度和停止条件时直接接续，不重问动机。直接使用本技能时承担同样的读取和自然收尾职责，不递归调度总控。只有一个缺口会改变研究路径时，先问那一个问题；已有明确点就围绕该点深挖。

例如：

- `使用 $research-traditional-sources 深拆这段《山海经》文字，重点看原文、旧注与后来解释的边界。`
- `我想知道这个器物的质感和使用动作是否有出处，别先写故事。`
- `接着上个阶段，只核对这两处异文及它们对理解的影响。`

## 研究推进

1. **固定所读对象。** 记录书名、作者或题署、版本、卷篇、叶面/页码、文件名与实际读取范围。数字平台分类、转录时间、注释者时代不能替代作品成书年代。原文与白话对照只取回答当前问题所需片段。
2. **分开时间与文本层次。** 按需区分故事设定时代、成书/编纂年代、现存版本或所读底本年代、现代研究年代；缺证据写未知。区分正文、注疏、辑佚、后世改编和现代研究，不把注里转引自动当作已读原书。
3. **读到支持判断的位置。** 先读前后文和注释归属，再检索出处、关键释义、必要背景与反证。重要论点必须有具体 locator；转述同一出处的多个网页不是独立证据。疑难文本与文化物件分别按 [专业核查规程](references/source-work.md) 执行。
4. **处理会影响理解的差异。** 对照相同文本单位与实际版本，保留各方原字、层次和出处。两份数字转录不同，只能先记电子文本差异；未核原页不能宣布古本异文或擅改原文。争议解释列出依据、冲突、取舍及无法确定处。
5. **形成贴题分析。** 区分文字实际记载、来源作者的解释、本执行者的分析、创作联想及未知。关联标为“文献支持 / 研究解释 / 仅相似”；不强造传承、影响或关系图。只有相似形状、同一字词、晚期传说，不能证明历史连续性。
6. **阶段交付。** 按[渐进阅读格式](../orchestrate-material-research/references/阶段写回协议.md#渐进阅读格式)分别写收藏预览与自足内容概要。故事用连贯白话交代已核人物、关系、情境、起因、经过、转折和结果；篇幅由内容决定，不按卡片长度压缩。原文缺动机或结局时明确未交代，后世阐释不倒补原故事。器物或民俗按对象、用途情境及关键特征适配，不硬套故事模板。概要之后给必要原文与紧邻白话，按论述自然组织章节；短原文可连读，不切成一串等权小卡片。再分层保留用户真实关注、专业解释、形式候选、版本争议及文化背景，来源细节后置，影响理解的疑点就近可见。原页或定位示意明确身份；不是删短报告或删除考据。交付前检查读者仅看稿件能否复述原故事/对象、区分正文与后世解释、找回来源。交给总控组装原合同stage；直接使用时由同一执行者CLI/API幂等提交、核收据并回读。版本冲突保留文件，重读合并，不覆盖旧成果或表单草稿。

## 来源入口与解析边界

- [Kanripo 目录](https://github.com/kanripo/KR-Catalog) 用于找书与底本；如 [KR3l0091](https://github.com/kanripo/KR3l0091) 是《山海经广注》文渊阁四库本。它是版本资料入口，不是 AI 研究工具；目录题署与年代仍须核对。
- [CText 相似段落](https://ctext.org/tools/parallel-passages) 用于提出文本关联线索。命中不证明谁影响谁，也不证明共同源头；随后实际读取两个出处与语境。访问受限则记录限制，不绕过，不把检索摘要当全文核对。
- 按需使用总控已有解析底座。Docling 等解析结果只是待核文本；古籍版式、小字注、异体字、缺字实体与 OCR 均要回看原页。缺能力时保留原件与定位缺口，不自动安装、下载模型或外传附件。
- 借鉴 [STORM 的多视角提问](https://github.com/stanford-oval/storm#how-storm--co-storm-works)：围绕当前论点分别问正文依据、版本问题、语境与反证，随后核实来源。不部署它的全文百科生成系统，不追加模型设置或付费检索。

## 回写的证据分类

沿用既有 `paragraphs/sources/sourceRefs/limitations`，不建另一套研究数据库。

| 内容 | 既有 basisKind 与写法 |
|---|---|
| 实际读取的原文、版本信息、馆藏说明 | `source_fact`，写“文本记载 / 馆藏说明”，并给原位置 |
| 实际观察原页上的字形、版式或物件局部 | `direct_observation`，明确仅观察了哪页/哪块 |
| 某位注释者或研究者的解释 | `author_interpretation`，标作者、时代、所读位置 |
| 本执行者的专业解释 | `ai_hypothesis`，heading 写“研究解释”，说明推理依据与反证 |
| 可带去创作的形式、质感或感觉线索 | `ai_hypothesis`，heading 写“创作联想·候选”，不写成已采用 |
| 小陌的原始吸引点 | `user_impression`，引用真实素材原话；演练自设关注点不能冒充 |
| 缺证据、不能判定的争议 | `unknown`，列出最小补证与停下理由 |
| 自制定位示意 | `demo`，标“非古籍原页”，来源仍映射到被示意文本 |

图片逐张标注原图/自制示意/推测图、来源与使用范围。原页不等于古代实物照片；推测图不用于证实器物形制。只保留必要引文和局部，不复制整本受版权保护的书。远程图不自动加载，网页图文用已登记 `attachment:ID`。

## 何时收束

本轮主要问题已有足够、可定位的回答，关键反证与未知已说明，且能够支持当前判断即可结束。不能访问关键原件、版本身份不清或核心结论缺依据时，保存已核内容和下一步，停止该断言；继续完成不依赖它的部分。

不替正式创作流程完成剧本、分镜或投稿。研究素材与真实学习进展各自保存。验收通过只证明本次规程与例子的表现，不自动认证题材穷尽、用户掌握或真实作品效果。
