# 图文阶段写回与接续

权威合同仍是项目 `素材观察室/共同读写规则.md` 与当前 CLI；不另建研究数据库。schemaVersion2 的既有段落、来源、附件与阶段字段足够，不要求旧成果新增字段。

## 读取与组织

以网页交接的准确 `identity/read-topic/read-material/read-attachment` 命令读取。只有 ID 相同不能确认库，须核 storeId/projectRoot/canonicalDbPath/schemaVersion/scope 五项。重读最近阶段所据素材版本；材料或专题变动时先比较。

把研究问题写 topic.question/scope；证据深度、模块、停止条件与实际工具/模型调用写当次 stage 的“范围与方法”正文和 limitations。停点写 focus/unknown/nextStep，下一步写可执行动作，不用“继续深入”代替。

stage.paragraphs 使用 heading/markdown/basisKind/sourceRefs/attachmentIds。五层证据对应现有判断类型：

- 可定位原文及文献记载用 source_fact，标卷页/真实文件行，转录不等于原页。
- 实际看到或听到的现象用 direct_observation，标帧/时间码与读取方式；只抽帧不能说连续看过。
- 有来源的他人解释用 author_interpretation；AI 自己的解释不可冒用。
- 当前专业解释与创作联想都用 ai_hypothesis，heading 再明确区分“分析解释”“创作联想（候选）”，逐句给支持、反例和不确定度。
- 小陌原话只引用原素材用 user_impression；unknown 标无法证实处。demo 仅明确的自制/隔离示例。

sources 按实际读取材料登记，sourceRefs 指实际支持段落的 sourceId、locator、note；多个页面转述同一材料不是独立验证。来源 licenseStatus 和 verificationScope 记录真实状态，访问失败的页写 limitations，不冒充已读来源。

## 渐进阅读格式

沿用 schema 2 的 `paragraphs[].heading/markdown/basisKind/sourceRefs/attachmentIds`，不增加 summary 字段，不要求重写旧成果。有正文的阅读成果阶段，前两段严格依次为 **收藏预览**、**内容概要**，分别承担列表辨认与详情理解。只保存停止处且没有正文的暂停记录，不要求编造这两段。网页兼容旧首段“这份素材讲什么”和无导读的旧成果。

1. **收藏预览单独写。** 用短而完整的自然语言让人辨认素材，按内容需要决定长度。它是卡片文字，不是详情概要的字数上限；不能裁详情首句冒充独立预览，也不能覆盖收藏时的原话。
2. **概要让人独立看懂。** 写成连贯、自足的通俗正文，长度随材料复杂度与已核证据决定，不硬套字数、段数或一句话模板。故事说明人物与关系、发生情境、明确的起因、经过、转折及结果；原文缺动机或结果时指出未交代，不编补。片段交代作品/片段身份、实际读取范围、可见或可听的局部内容及先后，不能借静帧或ASR编全片情节。物件交代对象、可核用途或情境和关键特征，不硬套故事结构。专名和理解所需背景就近解释。读者不用打开外链，也能复述已经知道的内容及关键未知。
3. **正文连续阅读。** 概要之后按理解顺序组织原件、说明、关注点、分析与考据。古文给必要原文并紧跟白话，画面给定位图并紧跟说明；短小原文可连读，不为凑栏目切成一串碎片卡片。长文按意义设自然章节和轻目录，标题交代内容；图、注和段落随论述就近出现。不要让工具名单、逐条状态和来源历史打断主体，也不把主体全部折叠。
4. **解释、兴趣与创作分层。** 原始事实、文献/他人阐释、当前专业解释、用户真实关注、创作联想（候选）分别标明。明确哪条形式线索可能可用、适用条件与尚未验证处；不把候选写成用户采用。影响判断的未知就近可见，末尾再完整记录读取范围与限制。
5. **来源可追。** 每段 sourceRefs 仍能定位到支持它的原处；原文配白话、图片配说明不能删去证据类型、时间码、卷页、许可和改动声明。正文可以用轻引用，完整来源与方法后置展开；不以笼统链接代替逐段对应。

可选的详细方法末尾组：作者把工具输出、执行记录及详细读取方法明确放到正文末尾，第一段 heading 严格为 **方法与读取记录**。网页把该段和其后段落合在文末一个可展开区，保留原ID、引用和附件，来源回跳自动展开。没有这个显式标记时全文继续展示，不凭标题关键词猜类别。影响理解的未知、正文释义、关键版本争议和专业分析仍就近可见，不把它们为缩短页面塞进方法组。

前两段最小形状如下，仅示意字段，不能把占位内容提交真实库：

```json
[
  {"paragraphId":"para_preview_本次唯一ID","heading":"收藏预览","markdown":"独立编写的卡片介绍。","basisKind":"source_fact","sourceRefs":[{"sourceId":"已定义来源ID","locator":"已核位置","note":"支持这项预览"}],"attachmentIds":[]},
  {"paragraphId":"para_overview_本次唯一ID","heading":"内容概要","markdown":"连贯交代已经核实的内容。\n\n随内容复杂度补足理解所需的经过、关系或情境；必要处交代关键未知。","basisKind":"source_fact","sourceRefs":[{"sourceId":"已定义来源ID","locator":"已核位置","note":"支持概要中的对应事实"}],"attachmentIds":[]}
]
```

basisKind 按实际证据选择，画面观察用 direct_observation，文献事实用 source_fact；分析或创作推想不伪装成事实概要。概要需要不同证据层时另设紧邻段落，明确区分，不在一段事实叙述内混入作者动机猜测。

交付前做内容验读，而非只查节点或字数：读者能否从稿件复述已知人物/对象、事情或片段进程？原文与白话、图片与说明是否对应？事实、后世解释、创作联想与未知能否区分？来源能否追溯？记录实际评审范围，不用结构通过宣称用户已满意。

用户要求重排已保存成果时，先备份、重读身份/版本/正文哈希；追加阅读阶段并保留原阶段、来源、原件及稳定专题ID。只改内容组织不构成新增外部研究或已完成新读听，未审听、未连续合看和版本未核状态保持。版本冲突先比较用户后来编辑，不改 expectedRevision 强行提交。

## 新图与原件

实际原页、关键帧或明确标记的示意图须走受控导入：

```json
{
  "identity": {"storeId":"从identity读取","projectRoot":"实际项目根","canonicalDbPath":"实际数据库","schemaVersion":2,"scope":"实际范围"},
  "submissionId":"新UUID；同原件重试保留",
  "filePath":"本地普通原件绝对路径",
  "permissionStatus":"来源许可与本次范围；未知就写unknown"
}
```

保存 UTF-8 JSON，再执行交接中的 `import-attachment --file` 命令。只有持久收据与回读明确成功后才用返回的 attachmentId；不猜路径或直接插表。许可字符串仅声明依据，不证明已获发布权限。派生帧定位必须保留原视频附件 ID/SHA、实际 PTS/时间码与裁取范围，不把每帧算一个独立来源。

Markdown 图片用 `![原图/关键帧/自制示意；具体位置](attachment:实际ID)`，同时列 paragraph.attachmentIds。未知引用不省略或随便换图；现有导出会收集真实内联引用和历史阶段原件。

## 准备、提交、回读

将 `handoff-topic` 的真实 JSON 与当次纯 stage JSON 存成绝对 UTF-8 文件，可用共用准备脚本形成一次不可覆盖的提交文件：

```powershell
node '<本技能目录>\scripts\prepare_stage.mjs' --handoff '<专题交接JSON绝对路径>' --stage '<stage JSON绝对路径>' --output '<新提交JSON绝对路径>'
```

脚本只准备内容，不导入图、不提交、不升级结构。不以准备成功宣称保存。它携带交接中的 identity/topicId/expectedRevision/materialVersions，生成并保存 submissionId；继续使用既有 CLI `submit-stage --file` 执行。长 JSON 不通过 shell 内联拼接。

每次研究新进展追加 stage。重试同内容保留完整提交文件和原 ID；若可能已提交但响应不确定，用同内容核对原收据。版本冲突整笔拒绝，保留原文件，重读合并后用新提交文件与新 ID，不能自动改 expectedRevision 后强推。素材原文、吸引点与旧阶段不通过研究修改。

检查 receipt、persistedSubmission、snapshotVerified；再 `read-topic` 核实际当前版本/新stage/图与来源。若又被更新，分别说明提交版本与当前版本。成功后提示网页“重新加载”，旧草稿由网页既有分支机制保留，本技能不得清网站草稿。

## 接续与范围

下一回合读本次 stageId、focus、已确认、候选、争议、nextStep 与原件，不归档整段聊天或依赖另一聊天私有存储。独立子代理/CLI读取证明协议与持久化，不能替代用户真的打开新聊天的验收。

建设验收默认写隔离库；不把测试自动塞入正式库。用户明确授权保存或修改指定正式案例时，只操作其指定 ID，并先备份、校验当前版本、追加阶段回读；其他素材保全。日常用户明确启动后的真实研究写其实际库。收藏/生成交接/创建专题本身都不等于研究授权。不更改学习记录、模型设置或正式影视工作流。
