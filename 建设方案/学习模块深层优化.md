## 核心用途和完成标准

现有个人情况记录，小陌希望看清有效进展，尤其需要帮助把庞大任务分类、拆开、串联并持续推进；同时已在自主看课、记笔记和创作中尝试应用知识。本人还自述缺少可靠的反馈标准。这些是设计依据，不是能力认证，见[个人情况](../运行记录/个人情况.md)。

建议按以下实际用途衡量本次优化。七个技能分别承担专业职责，使用时由同一对话按需组织。

| 核心用途 | 优化后需要做到的行为 |
| --- | --- |
| 决定现在做什么 | 根据当前目的、已有表现、材料、时间和精力推荐可完成的一步，并说明选择理由；只在影响决定时补问一个问题。 |
| 理解正在学的内容 | 定位当前课程或问题，读到相关正式内容，针对实际困惑解释；明确哪些判断来自原文、例子或推测。 |
| 把知识用于任务 | 优先利用已有作业或作品，选择能暴露当前困难的小应用；事前说明观察点、允许的帮助和停止处。 |
| 得到可信的反馈 | 沿用原目标和观察点看实际表现，区分理解、操作、综合取舍、材料、工具和时间问题；依据不足时保留未知。 |
| 根据结果继续或调整 | 保存具体材料、停点、疑问、结果与采用改法；下次能直接回到相关内容，并据实际表现调整学习与帮助方式。 |

学习可以从其中任一用途直接进入。纯答疑、自由看片和休息仍可独立发生，不要求每次走完整流程。维护信息的工作由系统承担，不转成逐课报备或用户填写表格。

## 当前已确认的结构事实

1. **七个学习职责已有较完整的原则。** 路线已有可观察目标和阶段够用依据；练习已有事前标准和反馈来源；能力判断区分概念、应用、迁移与帮助程度；复盘已有采用改法的跨主题接续。见[运行约定](../运行约定.md)及[七技能入口](../开始这里.md)。本次深化应复用这些机制。

2. **网页学习对象与正式记录没有完整绑定。** 正式课程记录已保存老白课“第六或第七节”的本人自述，课程架和空活动文案仍使用固定内容。`/api/bootstrap` 返回正式状态，但学习页启动仅使用连接配置。见[课程记录](../运行记录/课程记录.md)、[体验流程](../web/public/learning/体验流程.js)的 `renderDesk` 和 `renderCourses`、[学习集成](../web/public/learning/integration.js)的 bootstrap 处理。

3. **普通网页问答没有附带当前学习对象。** `sendChat` 发送原话、用途、近期历史和请求标识，未附带当前课程身份、活动、练习内容或关联资料。收尾按钮会拼入部分自述和下一步，仍不能提供完整材料。见[学习集成](../web/public/learning/integration.js)的 `sendChat` 和 `renderClose`。

4. **网页向导的取证范围有限。** `readContext` 固定读取个人背景、状态、安排和两份台账，附加总协调与最多两个专业技能正文；没有读取能力依据、对应活动记录、正式课程正文或作品片段的通道。系统提示也明确不能主动访问其他文件和工具。因此网页提供的帮助不能视为已经具备 Codex 内完整的专业取证能力。见[学习后端](../web/server.mjs)的 `readContext` 和 `buildMessages`。

5. **当前网页保存主要保留交流摘录和状态指向。** 学习记录保存 AI 回应最长 260 个字符的节选，安排另在阶段安排中保存较长正文；进展或收尾后的入口主要指向某日记录，不自动更新同一课程或能力依据。已有重复请求保护、失败重试和保存状态反馈，具体学习内容的接续仍需深化；不能据静态核对概括保证跨进程并发、断电与长期恢复。见[学习后端](../web/server.mjs)的 `recordText`、`updatePlan`、`updatedCurrentState` 和保存路径，以及[课程更新约定](../运行记录/课程记录.md)。

6. **尚缺系统内真实学习效果证据。** 当前正式阶段安排和能力依据未形成实际实例；[当前状态](../运行记录/当前状态.md)仍注明首次系统内学习交流与基于产物的能力判断待进行。[最新任务交付](../三系统工作台/真实任务可用性交付-20261003.md)证明收藏、研究交接、关联、比赛准备和恢复等路径能够完成，明确未验证个人学习效果。没有记录不等于小陌不会，也不能据此判定系统无效。

以上为本轮静态核对结果，没有调用真实学习模型或重跑浏览器验收。10 月 3 日已经修复的错专题、隐藏反向关联、转岛身份与刷新错对象等问题，不再列为当前缺口。

## 需要深化的判断机制

以下是结构风险，尚不能断言已在真实使用中发生。

路线、练习和能力判断分别规定目标或标准，但没有明确要求跨环节沿用同一组内容。可能发生目标是练习信息顺序，练习转为观察轴线，最后又评价画面美观的错位。候选改法是围绕同一项学习任务保留目的、材料、允许帮助和观察点；后续确需改变标准时说明原因，保留原标准与结果。

目前已有原因分类，但如何依据表现选择帮助仍依赖临场判断。候选改法是补强“证据支持什么解释、还存在哪些解释、最小的下一步能区分什么”这条决策链。例如知道原则却无法在片段中定位问题，与不知道原则，应得到不同的帮助。材料或工具造成的困难也应先处理对应条件，不能一律安排补课。原因不明时先分析已有结果，必要时补一个关键问题；额外检验仍以用户明确意图为前提。

判断“覆盖充分”还缺少具体任务基准。建议用小陌常见的起步、答疑、应用、反馈、中断后接续检查各职责之间的衔接；遇到某领域确有缺口，再深化对应的专业依据和练习方式。六岗位的范围说明不能直接证明所有综合任务都已支持。

## 候选实施次序

### 先让各入口使用同一份学习信息

按现有职责为课程、当前任务和产物建立明确对应。课程沿用已有编号，未知版本和模糊停点保持未知；当前屏幕的活动仅作为上下文，不因打开页面就确认进度或能力。

让课程架和接续入口读取正式记录；让向导知道本次讨论的课程、问题或练习。UI 草稿与真实记录继续分层，明确显示来源和保存状态。多入口共用业务依据，不把两个文件简单互相覆盖。

### 再打通相关材料和表现的读取

按当前问题读取相关课程正文、活动依据、能力摘要或用户指定的产物。读取范围应有边界，并能说明实际读到了什么；材料不足时仍能处理已有信息，不虚构课程内容或媒体审看。

知识树继续维护可复用知识，正式作品继续归创作工作流。本阶段只使用学习所需的受控引用，不迁移正文或另建作品工程。网页与 Codex 的帮助能力应明确区分；网页需要交给 Codex 的工作，要带上具体对象和问题。

### 深化目标与证据驱动的帮助

让路线、练习、反馈和复盘沿用同一任务范围和观察点。根据表现选择解释、示范、局部修改、综合应用或条件调整；帮助程度随当前目标和证据变化，不机械要求独立操作或固定次数通关。

收尾应从自然交流提取事实、疑问、采用安排和具体停止处，再按既有顺序保存依据与摘要。课程进度、能力判断和 AI 候选分别维护；保留原话与产物入口，不以简短总结替代全部依据。

### 最后验证学习用途能否完整完成

先在隔离环境验证读取、写入、重试和相关状态，再做真实材料的有界试用。现有保存、冲突保护和数据权威位置继续保留，必要变更先做可核验保护备份。

## 学习模块的验收场景

下表是待执行的验收设计，不是已发生的学习活动。它们独立可选，用于检查结构覆盖，不能要求小陌每天完成这些流程。

| 场景 | 应观察的结果 |
| --- | --- |
| 几个方向都想学，已有部分表现且现实容量改变 | 基于现有依据选择阶段与周重点，说明任务范围与够用依据；实际结果能影响路线和安排，不把候选方向自动采用。 |
| 时间有限且不知道先做什么 | 推荐的一步有材料和理由，任务量合适，未采用的长期方向保持候选。 |
| 继续一门已有课程并提出疑问 | 复用已有停点与不确定性；解释对应真实内容，必要时只核对影响当前决定的缺口。 |
| 带回实际练习或作品片段 | 按原目标定位有效之处和问题，区分实际表现与推测，下一步针对该问题。 |
| 时间变少或休息后回来 | 缩减或保留当前任务，找回停止处，未完成内容不自动成为欠账。 |
| 收尾后换会话继续 | 找回同一课程或任务、具体疑问和采用改法；计划、自述、判断和草稿不混淆，相关结果能影响下一步。 |
| 只想讲清一个问题或自由看片 | 当前请求得到帮助，不自动追加练习、测验、完整拉片或固定安排。 |

“本轮结构优化完成”建议要求：候选机制已经落实，当前确认的连接缺口有对应修复，代表性场景检查通过，剩余限制明确。真实试用另行说明启动负担、帮助质量与接续体验；一次使用不能证明长期能力提升。
