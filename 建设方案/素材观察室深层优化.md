# 素材观察室深层优化解决方案

> 当前状态：需求访谈前的技术候选，不是已采用的发展方向或实施计划。2026-10-03 小陌明确要求先结合最初需求和个人情况，通过多轮深入提问找寻真正需要，再对照已有功能决定优化方向。以下技术观察保留供访谈后筛选；本轮先进行需求访谈，不实施候选功能。

2026-10-03。小陌已选定素材观察室作为第二个深层优化模块。当前已完成现行入口、正式读接口、数据合同、阅读组件及三项深研技能的只读核对；以下候选尚未修改模块逻辑、数据库、附件或旧研究。具体目标、范围和主攻顺序由需求访谈继续澄清，不把技术建议写成小陌已确认需求或个人研究进展。

## 目标与边界

让素材观察室帮助小陌留住材料及自己的感受，独立看懂材料，围绕具体问题研究，暂停后准确接续，后来找得到并能取出有依据的一条线索。收藏、阅读和研究都可以独立发生；不是每条收藏都必须研究，也不是每项研究都必须进入作品。

网页承担日常收藏、原件阅读定位、成果阅读、找回和局部取用；Codex 承接专业研究与需要实际看听的分析。首版沿用现有分工，不默认增加网页模型聊天、自动 OCR/ASR、平台收藏采集、新模型或第三方外传。

保留素材与专题的稳定 ID、原始内容、原话及修正历史、备注、来源、旧阶段、附件和提交收据。原始内容、本人感受、AI 分析、研究成果和创作候选继续分层。学习与信息收集模块本轮不改；跨模块自动写回和晋升留到三个模块分别优化之后。

完成标准：当前用途链的连接缺口得到修复，代表场景能走通，实际成果经过完整内容检查及一轮本人试用。技术结构、内容质量、本人使用体验与作品实际效果分别报告。

## 当前依据与主要缺口

当前正式接口核对：`schemaVersion:2`、`scope:production`，10 素材、10 专题、16 阶段、26 附件，`store_4b9a06fd-0329-4a71-b32c-ef1a6f053d7d`。早期文档中的空库或 8/8/12/20 是历史轮次。现有案例主要是已授权的建设样板，测试关注点不能当成小陌的真实兴趣或使用反馈。

现有身份核对、SQLite 事务、版本冲突保护、持久提交收据、原话保护、不可覆盖的旧阶段、附件哈希和备份恢复适合保留。深层问题集中在这些机制之间：

| 当前断点 | 实际风险 | 当前定位 |
| --- | --- | --- |
| 专题问题与范围可修改，阶段未冻结当时问题 | 交接拼接旧 focus/nextStep 与新 question/scope，改题后可能继续错误方向 | `web/observatory/store.mjs` 的 updateTopic；`model.mjs` 的 validateStage；`cli.mjs` 的 handoff |
| 最新停点等同最新阅读成果 | 合法的空正文暂停阶段使默认阅读退回空记录，已有文章仍在历史中却不容易读到 | `web/public/observatory/app.js` 的素材概要及专题阶段选择 |
| 整个专题有正文被当作每条关联素材有研究 | 多素材专题只研究 A，B 也可能显示已有成果；同 URI 或共享附件也可能扩大判断 | `web/observatory/store.mjs` 的 withResearchEvidence |
| 来源范围靠自由文字声明 | 字段和引用通过不等于真实读过、听过或连续看过；本地取证输出尚未与阶段绑定 | `web/observatory/model.mjs` 的来源校验；深研 `inspect_material.py` |
| 研究所据旧素材版本难以直接读取 | 只能提示 revision 不同；旧阶段导出时可能配上当前素材内容，变动性质不明确 | `store.mjs` 的读接口；`portable.mjs` 的素材快照 |
| 搜索整段 JSON，而不解释命中 | 内部枚举词可命中全部案例，自然用途描述容易漏掉；原话、候选、旧结论与正文等权 | `store.mjs` 的 listMaterials/listTopics；`app.js` 的搜索 |
| 原件与关注点之间缺可验证定位 | TXT/MD 主要靠下载；时间标记无法直接跳到片段；图像局部与原件未稳定绑定 | `app.js` 的原件、关注标记与附件阅读 |
| 全历史附件检查与整包导出承担所有接续/取用 | 无关旧附件缺失可能阻断当前交接；取一条线索仍需人工摘录；候选缺采用依据和后续状态 | `cli.mjs` 的 handoff；`portable.mjs` 的导出；阶段字符串摘要 |

以上行为风险来自现行源码或只读构造核对，不表示小陌已在日常使用中遇到全部问题。Sintel 仍暂停于声音与连续合看缺口；Big Buck Bunny 的阶段完成仅指官方简介与离散预告帧范围，不等于正片审核。

## 一、围绕同一个研究问题持续帮助

复用 `topicId` 作为专题身份，不另建一套作品工程。把专题记录版本与研究问题版本分开：补标题或整理关联不等于换研究目标。用户明确调整问题或范围时保存新问题版本；AI 新方向先作为候选。

每次有意义的研究保留必要快照：当前问题、范围、关注对象、所需证据深度、够用条件、实际取得的依据、已有判断、重要未知、停止处和下一步。由系统与 Codex 从自然交流整理，不增加用户任务表。

旧阶段按当时问题与范围解释。改题后，接续明确展示新问题及可继承的旧依据；不把旧 nextStep 套到新目标，也不默认重做全部研究。尚未完成的旧问题可以暂放，原因及恢复条件可查。

按困难选择帮助，避免把“深研”统一成百科或长文：

| 当前困难 | 本次帮助 |
| --- | --- |
| 不清楚素材讲什么 | 先交代已读对象、关系、经过或用途，解释理解所需背景；缺失处不编补 |
| 古文、版本、名称或语境有疑问 | 对照相关原文与见证，解释差异如何影响理解；最早已找到记载不冒称确切起源 |
| 被一个画面、动作、声音或质感吸引 | 定位原件局部，观察关系和变化，比较可能解释；只取得静帧时停在静帧范围 |
| 想知道它为什么有效 | 给支持判断的原句或可见/可听现象、必要条件及一种有实质区别的解释，不把猜测当作者意图 |
| 已懂内容，但不清楚能借用什么 | 提炼少量具体形式线索、适用条件和改用后的取舍；不自动发展完整剧本 |
| 原件、声音或来源能力受限 | 说明哪项判断缺什么依据，完成仍可完成的部分，并留下可操作停点 |
| 当前问题已得到足够回答 | 在明确范围内收束，保留重要未知；不以段落数量或来源数量证明题材穷尽 |

继续复用素材总控、传统溯源、声画深拆三项项目技能，把会影响判断的规则落到共享合同。实际研究只在用户明确启动时发生，收藏、播放或复制交接都不自动触发。

## 二、把原件、关注点与实际依据连接起来

关注对象使用稳定素材/附件身份，绑定当时版本或哈希及定位。按材料使用文字行与原句、图片局部、媒体起止时间；定位变动时说明原锚点失效，不悄悄套到新材料。

先补受控 TXT/MD 原件阅读与定位、视频/音频标记跳转及图片局部定位。超出读取预算明确显示范围；不截断后冒称全文。链接暂时打不开仍可收藏，用户描述与外链实际内容分别使用。

研究来源增加可选的结构化读取依据，记录对象、版本/哈希、方式、范围、产物身份、取得时间和限制。复用现有本地读取脚本的文本、PDF、取帧与 PTS 输出；来源段落引用这一份实际依据，不能只有一条 URL 和“已读”声明。

三层分别维护：

- 工具实录：文件确实可访问，解析、取帧或转录实际执行及其范围。
- 执行者观察记录：实际查看、听审或连续合看的范围与方式。
- 研究判断：这些依据具体支持什么，哪些仍是解释、候选或未知。

程序校验身份、版本、范围与引用是否一致，拒绝明确矛盾的绑定；它不能仅凭声明或布尔值认证真实听审。语义内容仍需检查完整实际回答。抽帧不升级连续运动，ASR 不升级声音与表演判断，文本来源不能独自证明画面呈现。

派生能力按素材和片段计算：被关联、被实际读取、此局部已有成果分别显示。URI 相同或共享附件仅作为关系线索，不自动认证另一条素材的研究。没有充分对象对应的旧成果保留范围未知。

## 三、让停点、阅读成果与有效结论各尽其用

网页同时引用“最新接续点”和“当前可阅读成果”。新增暂停记录不挤掉已有文章；新增局部研究不要求重复提交全部全文。

新阶段区分研究推进、解释纠正、呈现修订和停点记录，明确继承、补充或撤回哪些旧依据与结论。阅读重排不计为新增读听，阶段次数不表示研究深度。无正文阶段用于接续记录，不能据此显示已形成内容成果。

首版可先可靠选择已有阅读版本，再展示明确关联的新补充与纠正；无继承/替代关系时不自动拼接不同版本。被纠正或撤回的判断仍可追溯，当前正文应就近说明，不埋在历史版本里。

阅读顺序继续沿用已采用规范：独立收藏预览、自足内容概要、原文与白话或图像与说明、必要专业分析、创作候选、影响判断的未知。来源和详细方法可以后置展开，核心解释不全部折叠。是否好读要看能否独立复述材料和判断依据，不以卡片或栏目齐全验收。

## 四、保存版本与后续变化的实际意义

新增受控历史读取，优先复用已有提交收据中的完整合法素材快照。`read-material --revision` / 对应 HTTP 接口返回所据版本、哈希与还原范围；缺失的旧版本明确 unavailable，不据当前版本倒填历史。

区分内容/原件/来源变化、关注范围变化、本人感受变化和整理元信息变化。补标签不默认要求重新研究；换依据不能沿用原结论当当前判断。旧用户原话仍保留，新感受也不覆盖旧研究当时所据原话。

导出和精确引用同时说明当时所据材料与当前材料；有历史版本就携带对应快照，没有就明示缺口。当前关联与历史研究依据关系分开，取消关联不让旧成果失去找回入口。

保留现有 SQLite 事务、CAS、持久提交收据与附件上传恢复，不复制学习模块的文件锁和日志。增加本库 `read-submission` / GET 提交回执，响应丢失后可先只读核对原处理结果，再决定是否按完整原内容重试。附件落盘与数据库提交仍是可恢复过程，不承诺跨附件和数据库的全局原子事务。

## 五、让后来找回与局部取用有依据

建立可重建检索读模型，只索引用户可见原文、标题、标签、原话、备注、研究正文及线索。内部 ID 和枚举不作为默认正文命中。

先实现字段检索、多词查找和明确的范围条件；自然问题只抽取可核对的检索条件，并显示实际使用范围。未知条件不能当肯定事实，词汇映射保留可解释规则。是否需要模型检索或向量服务由真实问句的漏召回决定，不预先增加。

每个命中返回对应句子、素材/专题/阶段/段落身份、版本、判断层次与匹配理由。默认区分当前成果与历史结果，历史可查且明确状态。点击能回到实际原句、原话或研究段落，而不只是打开一整篇文章。

局部取用复用稳定的阶段/段落引用，按需组织一条观察或一组“原文—解释”，携带实际依据、范围、版本、适用条件、未核项与候选状态。保留整包导出用于完整迁移，增加精确摘取以减少手工丢证据。

创作线索可引用、继续核查、明确采用、暂放或撤回；采用保留本人原话或明确操作依据，AI 提议不自动采用。采用也不代表该线索已在作品中有效。旧候选字符串继续显示，不自动补造采用历史。

本轮只交付模块内可取用成果，不自动写创作工作流、知识树或学习记录。三个模块分别优化后，再设计统一衔接。

## 六、接续只依赖当前必要材料

交接按当前问题、所选成果版本和实际需要组织素材与附件，完整历史仍可查询，不全部塞入每次启动词。

历史附件不可用时返回明确缺口，不因无关旧附件阻断整份交接。关键依据缺失则停止对应判断；仍能读取的任务身份、原话、旧成果与其他依据可以保留。缺失附件不能省略后声称完整覆盖，也不自动更换原件。

网页与 Codex 共用问题快照、读取依据与提交合同。新聊天先核库身份、问题版本、当前停点和已有阅读成果，再做唯一必要下一步。复制交接与实际新聊天执行分别验收，不拿子进程读取代替真实新会话。

## 实施顺序

1. **保护与契约。** 建立可核验一致性备份及代码保护，隔离恢复核对当前全表与 26 原件哈希；确定问题快照、读取依据、阶段作用及旧数据兼容。
2. **先修影响判断的连接。** 问题改变不串旧停点；暂停不隐藏已有正文；多素材/多片段的研究状态按实际依据派生；增加只读回执核对。
3. **接通原件与版本。** 文字原件阅读、关注点定位、历史素材读取、实际读取依据绑定及变更解释。
4. **整理阅读与当前成果。** 区分呈现修订、研究推进与纠正，承接旧文章和明确增量；完善必要材料交接和历史缺口提示。
5. **深化找回与精确取用。** 建立可解释检索、段落直达、线索引用及候选状态；保留完整导出。
6. **内容检查与试用后启用。** 在全新隔离副本完成接口、浏览器、失败恢复及代表场景，独立检查实际全文；再做有界本人试用，修正核心问题后启用。

优先用既有 JSON 可选字段和派生读模型；确需新增权威表时才做显式结构迁移。旧 ID、正文、原话、历史阶段与收据保留；缺少的问题快照、实际读取或采用依据标 legacy/unknown，不重写旧成果来凑新字段。隔离运行默认不调用真实模型、不采集、不写正式库，测试适配器只能明确注入。

## 验收与首轮试用

| 场景 | 必须达到 |
| --- | --- |
| 随手收藏 TXT 或暂时打不开的链接，过几天按一句印象找回 | 感受可空；收藏不研究；TXT 可直接读且定位；结果说明命中原话还是正文，不虚构外链内容 |
| 同一专题先解释原文，再明确改为形式观察 | 旧解释显示当时问题；新目标不继承旧 nextStep；有效依据可继承，未知与候选不变成新事实 |
| 有一篇文章后追加空正文暂停，再刷新或换聊天 | 旧文章仍可读，最新停点可见；新聊天接同一问题及缺口，不要求复制全文 |
| 一个专题关联 A/B，仅研究 A；同视频收藏两段不同片段 | B 不被认证已有研究；片段范围不串；共享 URL/图片仅形成相关关系 |
| 静帧研究后尝试补声音，但实际听音不可用 | 视觉部分保留，声音停在未知；不以提取、ASR、路径或手工声明冒称听过 |
| 补标签、修正本人感受或替换关注原件，随后查旧成果 | 分清变化性质；旧条件可读，缺版本不倒填；导出不无标识地混合新旧依据 |
| 当前必要材料可用，但一个旧无关附件缺失 | 交接返回缺口且其他部分可继续；依赖该附件的判断明确暂停 |
| 按“看过局部画面但没听声音”“原文与后世解释不同”找案例，摘取一条线索 | 不命中内部枚举；返回实句、位置、版本与限制；取用保留证据，AI 候选不自动采用 |
| 两端修改、响应丢失、重启、提交 ID 重试、损坏附件与错误数据身份 | 原有保护持续通过；只读回执可核对；冲突保留输入，不靠改版本强推 |

内容检查完整阅读实际答复及原件对应部分，覆盖：是否真的回答当前问题；读者能否复述已知材料；重要解释有无适用条件和另一种解释；是否把测试假设或 AI 改写当用户原话；是否虚构作者意图或未读内容；引用是否直接支持原句；是否为凑结构把物件/氛围强行改成完整故事。生成端不接收预期答案或错误清单。
