# 学习任务与判断契约

本契约供网页向导与七个学习技能共同使用。学习依据仍在本项目 Markdown，知识正文和正式作品保留在原系统。用户可以从安排、答疑、练习、反馈、回顾或欣赏直接进入；不要求每次走完全部环节。

仅留下课程笔记、看片感想或创作想法时，先走总协调的 [自然记录与接续](../.agents/skills/orchestrate-personal-learning/references/natural-recording.md)。内容条目编号、作品编号与学习 taskId 分别维护；纯笔记不要求 taskId，不因最近有任务而更新其目标或停止处。需要学习分析时再引用原条目及其原话，沿本契约判断，不重复登记经历。

## 围绕同一任务接续

可接续的任务由系统整理 taskId、目标版本、目的、课程或材料、已经展示的表现、允许帮助、观察点、停止处和下一步。不要让用户逐字段填写。单次纯答疑无需先建立持久任务。

taskId 跨天、暂停和调整时间保持不变。仅用户明确改变同一任务的目标或范围时增加目标版本；缩短时间、重新生成回复、AI 候选不改变版本。旧结果按当时的观察点和帮助条件解释。多个任务并存时先识别当前明确对象，不用最近一条记录覆盖所有学习。

路线、练习、反馈和复盘沿用同一目的与观察点。时间安排控制当次容量，不能为了适应短时间暗中更换能力目标或降低阶段标准。确需改变范围时说明原来与现在分别能观察什么，并保留改变依据。

保存节点保留所提供文字的完整原文、版本、作者来源和帮助条件。换会话时从同一任务的已提交活动恢复最近原文，本次提供新稿则优先使用新稿；恢复的旧材料不算本次新表现。结构更新失败时原任务摘要保持原值，已经保存的新版原文仍可接续。相同正文用于不同任务不能串用作者或帮助条件，活动文件变化后先重新读取核对。

## 根据实际困难选择帮助

| 当前依据 | 本次最小帮助 |
| --- | --- |
| 概念关系或条件混淆 | 读相关原文，解释关键关系和一个贴近材料的对照。 |
| 会说明原理，难以在现有片段运用 | 定位一处观察对象，示范判断依据，给一个局部应用方向。 |
| 操作失败或输出不符 | 核对操作、材料、参数和工具能力，区分知识缺口与条件限制。 |
| 单项可以，组合后接不上 | 在现有作业或作品中找一个衔接断点，选择小范围完整应用。 |
| 原观察点仍未满足 | 说明具体差距，建议局部修改或调整条件，并说明取舍。 |
| 在允许帮助下已经满足当前关键要求 | 说明够用范围及未决问题，建议继续或转向；不认证所有情境都稳定掌握。 |
| 只有完成自述、感觉变化或原因尚不明 | 保留未知，先分析已有内容，只补问会改变行动的一点。 |

原因判断要说明哪些观察支持它，仍有哪些有实质区别的解释。普通答疑不附加考试；用户明确要检验时一次一题，等回答。额外练习、换材料或减少帮助必须服务于当前目标，不设固定次数、分数门槛或复习欠账。

阶段路线说明为什么投入、希望能做什么、怎样看出当前够用。周安排选择现实容量内的推进重点；当次取能完成的一步。没有长期安排也可直接开始。优先已有课程、作业、笔记或作品，不重复布置相同任务，不以记录空白要求全面重学。

## 让专业判断有依据

课程问题使用当前正式课级正文及相关章节；目录用于导航，旧总结不能替代新版正文。读取必须覆盖支持判断的方法和不可分割的条件，保留实际文件、章节、行范围和版本。检索命中、来源链接或文件存在均不证明内容已经足够。

用户课程编号与知识库课程版本分别维护；同名资料未经核对仅作资料候选，不推断本人课次、观看完成或掌握。材料不足时区分通用解释与尚未核对的课程含义。

影视问题按需使用现有专业参考。普通讲解优先原课与只读讲解方法；明确应用查理第 2—10 课的方法时可读取相应专业参考，但不把执行协议冒充老师术语，也不将局部文字片段强行扩成整部八要素或十序列审核。其他课程或章节按本次实际选定内容处理。

文字、静帧、路径和 ASR 不能替代原声听审、连续声画或实际受众反馈。网页文字向导只判断已提供文字与实际读到的笔记；复杂媒体分析交给 Codex，交接保留任务、材料版本、具体问题和停止处。没有获取的反馈保持未知。

## 区分事实与建议

用户原话、用户自述、实际可见产物、AI 判断、候选和采用分别保存。解释由 AI 给出，不等于用户已经理解；AI 替写的内容不等于用户独立完成。否定、假设、模糊范围及未知帮助条件不得被抽取为确定事实。

反馈先回应实际有效之处和最值得处理的问题，用具体位置与依据说明影响，给可执行的下一步。形式随需要变化，不强制每次展示固定表格。审美偏好、原课观点、可核对事实和推测分别表达；作者已有合理取舍时可以不改。

检查剧本时同时核对作者已写明的意图和具体动作。正文已写出意图，不能称为文字漏写；需要进一步讨论时说明它是否已转成可拍、可辨认的行为，这属于呈现判断与待验证取舍。局部补充或换动作的耗时未经朗读、预演或真实计时前，不承诺能装入原预算或总时长不变。

明确请求的安排保存为待执行；用户明确改变方向或方法直接落实，AI 自行提出的目标和改法保持候选。长期偏好不因一次疲劳或小样变化自动改写。

复盘回到原观察点，比较实际尝试、结果、帮助程度和材料条件。只把已采用的改法接回阶段安排同一条目。没有结果不写有效；一次顺利不证明普遍因果。休息或空白记录不形成欠账，自由看片不追加作业。

## 统一提交与失败恢复

网页与 Codex 使用项目内学习 CLI/提交器维护正式记录。只读命令不创建记录。保存从活动原始依据开始，随后仅更新有实际变化的课程、安排和能力摘要，最后更新当前状态并回读。

轻量笔记与内容登记通过统一 intake 分流：课程 note 由原学习提交器保存，观看和创作交原 ContentStore。笔记原话与 AI 解释分层，未知身份与日期不补造；不以笔记保存推断课程完成、能力进展或方案采用。回执须能定位同一网页条目，准备结果和模型回复本身都不是保存成功。

模型返回受限的更新候选，本机服务核对原话、任务、证据和版本后提交；不执行模型提供的任意路径或整文件替换。结构失败可在自然保存节点保留原始交流依据，但不能猜出课程更新或能力结论。

同一请求重试复用完整答复和提交回执。跨进程锁与逐文件旧、新哈希支持中断恢复；出现第三种内容时保留当前文件并报告冲突。它是可恢复提交，不是任意编辑器条件下的全文件原子事务。

用户说本次不保存时不写正式活动、台账、任务或含个人正文的提交日志。界面近期交流按已有 UI 接续规则保存，与正式学习记录分开。系统建设和隔离测试不进入个人学习进展。
